# RupeeTrace — Visual Money Trace Graph Redesign Specification

## 1. Executive Summary & Design Principle

The original Money Trace Graph attempted to visualize all entities (wards, roads, work orders, contractors, complaints, and audits) on a single SVG canvas. This resulted in an unreadable "hairball" graph, severe browser render lag, and cognitive disorientation for investigators.

The redesigned **Scoped Entity Investigation Board** enforces the core architectural principle:
> **Never load the entire municipal dataset by default. Every investigation begins with a specific anchor entity and reveals its direct 1-hop operational neighborhood.**

---

## 2. Six Scoped Investigation Modes

| Mode ID | Root Entity Type | Radial Direct 1-Hop Connections | Key Forensic Question Answered |
|---|---|---|---|
| `road` | Road Asset (e.g. `RD0140`) | Linked Work Orders, Empanelled Contractors, Citizen Complaints, Active Audit Flags | Where did the money spent on this specific road go, and did the repairs hold? |
| `work_order` | Work Order (e.g. `WO25-00600`) | Parent Road, Assigned Contractor, Parent Ward Budget, Triggering Citizen Complaint, Audit Finding | Why did this contract experience a +129.5% cost variance over the rate card? |
| `contractor` | Contractor (e.g. `CT01`) | Active Road Work Orders, Operating Wards, Audit Irregularities | Does this contractor hold a municipal monopoly in Ward K/East? |
| `complaint` | Citizen Complaint (e.g. `BMC25-000005`) | Reported Road Segment, Resulting Work Order Repair, Complainant Category | Did BMC actually dispatch a repair contractor for this pothole complaint? |
| `ward` | Ward Budget (e.g. `K/E`) | Top Road Assets, Empanelled Contractors, Major Work Orders | How was the ₹0.91 Cr monsoon repair allocation distributed across contractors? |
| `audit` | Audit Finding (e.g. `AUD-01`) | Flagged Work Order, Breached Contractor, Impacted Road Asset | Which contractor breached the 2-year Defect Liability Period warranty? |

## 3. Progressive Disclosure Architecture

```
[Start Entity: RD0140] (Center: 450, 320)
       |
       +--- 1-Hop: WO25-00600 (Contract Repair)
       +--- 1-Hop: CT01 (Apex Infrastructure)
       +--- 1-Hop: BMC25-000005 (Citizen Complaint)
       +--- 1-Hop: AUD-01 (Rate Deviation Audit)
       |
       [Action: Click Node -> "Expand Connections"]
       |
       +---> 2-Hop: Related Sub-contracts, Historical Repeat Complaints
```

1. **Initial Load**: Centers root entity at `(450, 320)` with its immediate 1-hop dependencies positioned radially at radius `R = 220px`.
2. **Expansion**: The user selects any peripheral node and clicks **"Expand Connections"**. The client sends `expanded_nodes=[node_id]` to `/api/graph/investigate`, revealing the next hop without resetting current viewport zoom or pan.
3. **Category Filtering**: Interactive category pills toggle node visibility (Ward Budget, Road Asset, Work Order, Contractor, Citizen Complaint, Audit Finding).

---

## 4. Separation of Deterministic vs ML Relationships

To prevent false accusations in public municipal procurement:
- **Deterministic Relationships**: Solid dark line (`#171717`, width `2.5px`). Backed by verified BMC SAP work orders, road registries, or treasury vouchers.
- **ML Candidate Relationships**:
  - Gated behind an explicit **"Include ML Candidate Links"** toggle (OFF by default).
  - Styled with high-contrast **dashed crimson lines** (`#FF3B30`, stroke-dasharray `6,4`).
  - Labeled with explicit confidence scores (e.g., `ML Match: 84% (Probable Duplicate Issue)`).
  - Prominent disclaimer displayed in the inspector drawer: *"Candidate link generated by Multilingual Issue Intelligence embedding model. Requires officer verification."*

---

## 5. Contextual Inspector Drawer & Forensic Table Alternative

- **Right-Side Inspector Drawer**: Selecting any node or edge displays full municipal metadata, dates, monetary values, contractor empanelment years, audit recommendations, and direct links to evidence modals.
- **Forensic Table View**: For investigators who prefer structured rows over visual graphs, the **"Forensic Table"** button renders an interactive sortable ledger of all nodes, categories, and direct connections.
